# Type9 — handoff

Состояние на **v0.4.0** (25.11.2026). Документ для того, кто продолжит разработку.
Репозиторий: https://github.com/DenHaIz/Type9 · автор коммитов: `denhaiz`.

## Что это

Резидентная программа для Windows (трей): глобальное автодополнение в любом поле ввода (как T9) + круговое меню
готовых фраз по горячей клавише (как buy-menu CS:GO / chat wheel Dota 2). C# / .NET 10 / WPF, без сторонних
NuGet-пакетов в приложении. Выпускается **один самодостаточный `Type9.exe`** (облегчённая framework-dependent версия
убрана по решению владельца).

**Приоритеты владельца:** стабильность и скорость > потребление памяти > размер exe. Интерфейс — RU/EN, тёмная/светлая
тема, бордовый акцент по умолчанию, плавные анимации на каждое действие (рассчитаны на 60 Гц).

## Как выпустить версию

1. Поднять `<Version>` в `src/Type9/Type9.csproj` (формат `0.X.Y`; тег — `v0.X.Y`) и версию в строке загрузки README.
2. Переписать `docs/RELEASE_NOTES.md` — он становится текстом релиза. Требование владельца: **коротко, 1–3 строки,
   одинаковый текст на двух языках** (абзац **RU** и абзац **EN**), без BOM. README тоже держать коротким и двуязычным.
3. `dotnet test Type9.sln` и `.\build\build.ps1` локально.
4. Коммит от `denhaiz <denhaiz@users.noreply.github.com>`, без строк соавторства; `git tag -a v0.X.Y -m "Type9 v0.X.Y"`;
   `git push origin main` и `git push origin v0.X.Y`.
5. Workflow сам соберёт exe, посчитает SHA-256 и создаст релиз. Установленные копии обновятся в течение 6 ч
   (или сразу по кнопке «Проверить сейчас»).

## Языковая модель

Пересборка (данные в репозиторий не кладутся; ~2,5 мин и ~4 ГБ ОЗУ на язык):

```powershell
# ru_full.txt / en_full.txt — github.com/hermitdave/FrequencyWords (content/2018/<lang>/<lang>_full.txt)
# rus_sentences.tsv / eng_sentences.tsv — downloads.tatoeba.org/exports/per_language/<lang>/<lang>_sentences.tsv.bz2
# *-sentences.txt — downloads.wortschatz-leipzig.de/corpora/<имя>.tar.gz:
#   rus-ru_web-public_2019_1M, rus_news_2023_1M, eng_news_2023_1M
# --corpus путь:вес_в_n-граммах:доля_в_частоте_слов ; --freq путь:доля
dotnet run -c Release --project tools/DictBuilder -- --lang ru --freq ru_full.txt:0.35 `
    --corpus rus_sentences.tsv:2:0.15 --corpus rus-ru_web-public_2019_1M-sentences.txt:1:0.3 `
    --corpus rus_news_2023_1M-sentences.txt:0.5:0.2 --extra tools/DictBuilder/business_ru.txt `
    --vocab 200000 --maxbi 1600000 --maxtri 1600000 --holdout 400 --holdout-out holdout_ru.txt `
    --out src/Type9/Resources/Dict/ru.t9lm
dotnet run -c Release --project tools/DictBuilder -- --lang en --freq en_full.txt:0.45 `
    --corpus eng_sentences.tsv:2:0.25 --corpus eng_news_2023_1M-sentences.txt:1:0.3 `
    --extra tools/DictBuilder/business_en.txt --vocab 120000 --maxbi 1200000 --maxtri 1000000 `
    --holdout 400 --holdout-out holdout_en.txt --out src/Type9/Resources/Dict/en.t9lm
```

- RU (v0.4): 200 000 слов, 1,26 млн биграмм, ~1 млн триграмм; файл 10,7 МБ, в памяти ~29 МБ (было ~13), загрузка ~0,4 с.
  EN: 120 000 / 1,09 млн / 0,87 млн, ~22 МБ. Формат `.t9lm` v2 (v1 тоже читается). Биграммы в памяти — CSR
  (`_biStart`/`_biNext`), без 8-байтовых ключей.
- Частота слова — смесь долей источников; n-граммы — с весами корпусов (внутри ×2, чтобы допускать вес 0,5);
  пороги подбираются под `--maxbi/--maxtri` (не меньше двух употреблений). `--holdout N` откладывает каждое N-е
  предложение корпусов в файл для оценки (в модель они не попадают).
- **Форма для показа**: самая частая строчная (с ё — по частотному списку); имена собственные (заглавная в середине
  предложения ≥ 85 %, от 30 употреблений) — «Москве»; аббревиатуры (капсом ≥ 70 %, от 10 употреблений, до 6 букв) — «ООО».
  Имена из корпуса не предлагаются следующим словом (только если пользователь сам их писал).
- Имена, которыми переполнен Tatoeba («Том», «Мэри»…), исключаются только в заглавной форме — «о том» остаётся.
- **Окончания** (согласование без морфологического словаря), множители к оценке кандидата:
  1) `ContextSuffixLift` — профиль окончаний у продолжений *этого* слова или пары в корпусе («согласно» → «-у/-ю»,
     «в соответствии с» → «-ми»), сглаженный моделью классов P(2 последние буквы | 3 последние буквы предыдущего);
  2) `SkipSuffixLift` — то же через одно слово («поиском и возможност**ью**»), в степени 0,5.
  Классы реже 50 употреблений не хранятся. Степени: `LiftPowRu` 0,6 (EN 0,4), доля для контекстной части 0,4.
- **Оценка** (2000 отложенных предложений веба и новостей; старая модель → новая): следующее слово в топ-3
  9,5 → 16,7 %; нужное слово в топ-3 после 2 букв 28 → 41 %, после 4 букв 50 → 64 %; «основа верная, окончание
  нет» после 4 букв 27 → 21 %; ложные исправления правильных слов 1,9 → 0,9 %; подбор ~1,5 мс (было ~0,6).
  Подбор весов окончаний давал ±0,5 % — у подхода «по буквам окончания» потолок; дальше — морфология (см. «Идеи»).
  Харнесс оценки не в репозитории: консоль, которая на каждом слове отложенных предложений вызывает
  `PredictionEngine.Predict` (без префикса, с 2 и 4 буквами) и считает попадания.
- В памяти — только модели выбранного языка подсказок. Источники: FrequencyWords — CC BY-SA 4.0, Tatoeba — CC BY 2.0 FR,
  Leipzig Corpora Collection — условия на wortschatz.uni-leipzig.de (сайт закрыт от автоматического чтения —
  **лицензию нужно перепроверить вручную**). Ссылки на источники — в «О программе».

## Обучение на тексте пользователя

- Слово попадает в очередь при завершении (пробел/знак), а **фиксируется**, когда начато следующее слово
  (`CommitDistance` = 3 символа), после паузы 1,5 с (`AppController._learnIdleTimer`) или при уходе из поля/клике.
- Backspace в ещё не зафиксированное слово, Ctrl+Backspace, Ctrl+Z, ←, Home, Delete — это правка: очередь выбрасывается.
- Не учится: поля паролей (Win32 `ES_PASSWORD` сразу; браузеры/Electron — через UIA при каждой смене фокуса,
  до проверки очередь не фиксируется), программы-исключения, адреса/почта/пути (`CompletedWord.Learnable`), смесь алфавитов.
- Последнее слово перед кликом / сменой поля / Ctrl+сочетанием (сообщение отправлено кнопкой мыши) тоже учится
  (`CompletedWord.Tentative`), но только если оно известно модели, деловому словарю или пользователю — оборванное
  «догов» не запоминается.
- Незнакомое модели слово от 4 букв предлагается сразу после первого употребления, если оно не похоже на опечатку
  частого слова (`Corrector` ничего не находит); иначе — со второго. Пользовательский контекст сглажен (+2).
- **Регистр в словаре** (`UserModel.PickForm` → `CaseHelper.CleanCase`, словарная форма — `PredictionEngine.KnownForm`):
  капс слова словаря → строчные («ЧЕРЕЗ» → «через»), «дА»/«пРИВЕТ» (CapsLock + Shift) → «Да», аббревиатуры — как в
  словаре («ИНН»), незнакомый капс до 5 букв остаётся («СНИЛС»), длиннее — строчными. Старые словари чинятся при загрузке
  (`FixForms`, когда загружены и словарь, и модель).
- Обучение на тексте и импорт разбираются в фоне в отдельную модель и вливаются `MergeFrom`; удаление выделенных слов —
  один проход по n-граммам (`RemoveMany`).
- `UserModel.Prune`: при > 150 тыс. слов удаляются разовые слова старше 60 дней.
- Словарь не сохраняется, пока не загружен (слова, выученные во время загрузки, сливаются); при ошибке чтения файл
  копируется в `.broken`, сохранение отключается до перезапуска.

## Регистр и опечатки

- **Регистр** (`CaseHelper.Apply`): капс набранного не переносится — «ДОБ» → «Добрый» (слово заменяется целиком).
  Причина: регистр набранного мы знаем по своему отслеживанию CapsLock, а оно теряется, если CapsLock переключили мимо
  хука (окно администратора, экран блокировки, синхронизация RDP). Слова с заглавными внутри («iPhone», «ОГРН») не трогаются.
- **CapsLock** (с 0.4): регистр переключается по *отпусканию* клавиши и только если её нажатие дошло до системы
  (`GetAsyncKeyState(VK_CAPITAL)` в этот момент показывает «нажата»). Переключатели раскладки «по CapsLock» и
  переназначения клавиш «съедают» её уже после нашего хука (сторож переустанавливает хук — мы оказываемся первыми);
  раньше регистр у нас при этом переворачивался, и в личный словарь попадали «ЧЕРЕЗ», «дА». Дополнительно таймер 300 мс
  читает `GetKeyState(VK_CAPITAL)` и правит отслеживание (`InputEngine.SyncCapsLock`), когда состояние в системе сменилось
  (RDP, экран блокировки). «пРИВ» (CapsLock + Shift) считается набранным с заглавной. Вживую не проверено.
- **Заглавная в начале предложения** (`AutoCapitalize`, `TypingContext.SentenceStart`): только после явного «. », «! »,
  «? », «… » или перевода строки, увиденных в хвосте. Пустой хвост (после клика) не считается; точка после одной буквы
  («т.е.», «г.») — сокращение.
- **Опечатки** (`FixTypos`, `Corrector.Find`): варианты на расстоянии одной правки (лишняя/пропущенная/заменённая буква,
  перестановка соседних). Вес правки: замена соседней клавиши 1,0, далёкой 0,45; лишняя буква 0,9 рядом с соседней/двойная,
  иначе 0,6; пропуск 0,8. Исправление предлагается, если оно в 30 раз частотнее набранного (или лучшего его дополнения)
  и не реже 1e-6; слова короче 5 букв не трогаются; в словах короче 6 букв — только вероятные правки (вес ≥ 0,8).
  Исправление — всегда первым; остальные места — дополнения набранного (без слабых: оценка < 1/300 исправления и нет
  поддержки контекста/личного словаря); второе исправление — только если не хуже 0,3 первого. Вариантов не больше
  настройки. Слова делового словаря получают при проверке не меньше его частоты. Слова пользователя
  (2+ употребления), его словарей и делового словаря опечатками не считаются.
  Сразу после пробела (`TypingContext.Gap`: пробел или «, » и т.п.) можно исправить только что набранное слово —
  `Backspaces` = слово + разделитель. Для Tab+цифра `TabAccept.Erasable` хранит стираемый текст целиком.
  Слова корпуса без контекстной поддержки, у которых есть «правильный» сосед (опечатки из субтитров вроде «здраствуйте»),
  из дополнений исключаются.
- **Деловой словарь** (`Resources/Dict/ru.business.txt`, `PredictionEngine.Supplement`): жаргон и термины, редкие в
  корпусах («бэкап», «учётка», «растаможка»), и аббревиатуры в правильном регистре («ООО», «ЭЦП», «КоАП»).
  Слово получает частоту не ниже 2e-5 × (1 для первой формы строки, далее −0,1); форма с заглавными побеждает форму корпуса.

## Подсказки: клавиши и запятая

- `Tab` вставляет выбранный вариант сразу по нажатию. Пока Tab зажат, цифра 1–9 (и на цифровом блоке) **заменяет**
  вставку вариантом N (`InputEngine.ReplaceAccepted`: стирает вставку, возвращает стёртые буквы, печатает другой вариант);
  автоповтор Tab после вставки поглощается. Любая другая клавиша или отпускание Tab завершают режим.
- Колесо мыши над плашкой листает варианты (дельта копится до 120 — тачпад не пролистывает всё сразу); страница под
  плашкой при этом не прокручивается. `↑/↓` по-прежнему работают.
- **CapsLock листает варианты** (настройка `CapsLockCycles`, по умолчанию выкл.): при видимых 2+ подсказках нажатие
  выбирает следующий вариант по кругу и поглощается вместе с автоповтором и отпусканием (`InputEngine._capsCycling`).
  Если подсказки после последней буквы ещё пересчитываются, нажатие всё равно поглощается, а шаг применяется к новым
  вариантам (`_capsPendingSteps` → `SetSuggestions(..., out selected)`),
  регистр не меняется. Без подсказок, с модификаторами или если CapsLock назначен на меню — обычный CapsLock.
  Строка подсказки внизу плашки — `Pop.HintCaps`.
- **Запятая после приветствия** (`Greeting.NeedsComma`, настройка `GreetingComma`): «здравствуйте/привет/приветствую/hello/hi»
  в начале предложения и пары «добрый день/вечер», «доброе утро», «good morning…» (допускается «всем» перед ними).
  Запятая есть и в дополнении слова, и в подсказке следующего слова. Если сразу после вставки набрать `,` `.` `!` `?` `:` `;`,
  наша запятая (и авто-пробел) заменяются этим знаком: «Здравствуйте!» (`InputEngine._autoComma`).

## Горячие клавиши меню

- Обычное сочетание (Alt+Q и т.п.) поглощается; после Alt/Win шлётся «пустая» клавиша VK 0xE8 (не открывается меню окна/Пуск).
- **Одиночный модификатор** (`Hotkey.IsSingleModifier`: RCtrl, RAlt, LWin…) не поглощается: меню открывается через 140 мс,
  только если клавиша всё ещё зажата одна (`InputEngine._otherKeyDuringHold`, `AppController.OnRadialOpen(delayed)`);
  в режиме «нажатие» — по отпусканию «чистого» нажатия. RCtrl+C и т.п. работают как обычно.
- F-клавиши, CapsLock (тогда не переключает регистр), кнопки мыши — хоткеи без модификаторов; буквы без Ctrl/Alt запрещены.
- `HotkeyBox` записывает модификатор по его отпусканию; `HotkeyAdvisor` показывает предупреждение о конфликте.

## Круговое меню на экране

- `RadialMenuWindow.Place`: монитор под курсором, его DPI (`GetDpiForMonitor`), окно ставится на место ещё скрытым
  (WPF заранее получает DPI — без «прыжка»), целиком в рабочей области (за край уходит только поле тени).
- Перед открытием ждём каретку до 90 мс; если меню перекрыло бы строку — ставим выше/ниже (где ближе и помещается).
- Если меню сдвинуто относительно курсора, курсор переносится в центр и возвращается после закрытия.
- Подсветка выбора (с 0.4): одна фигура-сектор на слой (`RadialView._hl`) между фонами секторов и подписями.
  Анимируется **покадрово** (`CompositionTarget.Rendering`, только пока есть движение): угол и прозрачность подсветки
  и цвет подписей экспоненциально догоняют цель (τ ≈ 40–60 мс). При быстром ведении мыши ничего не перезапускается,
  на смену сектора нет новых раскадровок. Прыжок > 100° — проявление на месте. `HitIndex` с гистерезисом: выбранный
  сектор держится, пока курсор не ушёл за его край на 4° (или на 6 DIP вглубь центра) — на границе выбор не мигает.
  Смена страниц — перекрёстная анимация двух слоёв с BitmapCache.
- Превью колеса в настройках — тот же `RadialView` с `Lightweight="True"` (без тени и BitmapCache) и `TextBoost`
  (крупнее подписи), в Viewbox фиксированного размера 264×264 без округления раскладки.
- Стандартный набор — 3 группы по 8 фраз (Приветствия, Ответы, Завершение); `PhraseBook.CurrentDefaultsVersion = 4`,
  нетронутые наборы v0.1–v0.3 (`LegacyPhraseTexts` + `V3PhraseTexts`) заменяются при запуске.

## Положение плашки подсказок

`CaretLocator.Locate`: (1) `GetGUIThreadInfo` → `Win32.ClientToPhysical` (перевод в контексте DPI чужого окна +
`LogicalToPhysicalPointForPerMonitorDPI` — иначе в DPI-unaware программах при 125–150% плашка смещена); каретка вне
окна или в (0,0) отбрасывается. (2) UIA TextPattern (символ слева/справа от каретки). (3) Если точной позиции нет —
`Fallback`: последняя точная позиция в том же поле или место последнего клика в этом окне (`NoteClick` из хука мыши),
что новее; затем примерная позиция UIA; мышь — только в крайнем случае. Так плашка не прыгает между источниками.

`MinLine`: каретка ниже ~14 DIP дотягивается до высоты строки (18 DIP). Qt-окна (класс `Qt*QWindow*`, Telegram) ставят
системную каретку для диктора, но её вертикаль неточна — плашка наезжала на строку. Для них дополнительно спрашиваем
UIA: точная позиция берётся, если она рядом с системной кареткой; иначе низ каретки опускается до низа однострочного
поля (высота < 3 строк). Проверить вживую в Telegram не удалось (сессия без рабочего стола).

## Ключевые решения

- **Хуки на отдельном потоке** + сторож: раз в минуту простоя хуки переустанавливаются (Windows молча снимает LL-хук
  при таймауте). Принятие подсказки (SendInput) — прямо в колбэке, чтобы сохранить порядок нажатий.
- **Свои вводы не обрабатываются** (`dwExtraInfo == InjectionMarker`); чужие инжектированные (RDP, AutoHotkey) — обрабатываются.
- **Версии контекста**: подсказки применяются и принимаются только для актуального `InputEngine.Version`.
- **Наведение мыши на плашку не меняет выбор для Tab.**
- **Скорость**: ReadyToRun, прогрев после загрузки модели, GC `SustainedLowLatency`, фоновая сборка, рабочий набор
  не урезается. Подсказка ≈ 6 мс в худшем случае (префикс из 1 буквы).
- **Темы**: кисти в ресурсах приложения WPF замораживает → заменяются; плавность — кросс-фейд снимка окна настроек.
- **Чёткость при масштабе** (`UiScale.PixelAlign`): масштаб интерфейса — LayoutTransform на самом внешнем элементе окна,
  а окну через `VisualTreeHelper.SetRootDpi` сообщается DPI × масштаб. Тогда WPF округляет раскладку и растеризует текст
  сразу под реальные пиксели (иначе при 90/115/130% и масштабе Windows 125/150% рамки «плывут», текст мылится).
  Следствие: `VisualTreeHelper.GetDpi` в этих окнах возвращает DPI × масштаб — для физических пикселей экрана
  использовать `UiScale.DeviceScale`. Кеши `BitmapCache` (тень плашки, диск колеса) получают `RenderAtScale` = этот DPI.
  Шрифт — Segoe UI (вариативный Segoe UI Variable WPF рисует хуже), минимальный размер текста 11,5–12.
- **Вставка фраз**: ждём отпускания модификаторов; длинные (> 200 символов) — через буфер обмена с сохранением всех
  форматов; если буфер занят — печатаем.
- **Автообновление**: через 20 с после старта и раз в 6 ч; без SHA-256 и без права записи в папку exe — не ставится;
  exe переименовывается в `.old`, новый запускается с `--restart --updated <версия>`; данные в %AppData% не трогаются.
- **Single-file без сжатия**: со сжатием сборки распаковываются в память (+~80 МБ RAM).

## Известные риски

- **Память**: модель RU ~29 МБ (была ~13). Если нужно экономнее — `--maxbi 900000 --maxtri 700000` даёт ~23 МБ ценой
  ~1 п.п. точности.

- **Ложные исправления**: редкое настоящее слово, похожее на частое, получит «исправление» первым вариантом
  (например, «страхуй» → «страху»). Это только подсказка, не автозамена; пороги — константы в `Corrector`.
- **CapsLock**: проверка «нажатие дошло до системы» и сверка `GetKeyState` не проверены вживую. Капс в подсказках
  и в личном словаре в любом случае не появится (см. «Регистр и опечатки»).

- **Зависание раздела «Круговое меню» (v0.3.1, у пользователя; 100% масштаб, свой набор фраз)** — у разработчика
  не воспроизвелось ни в одной конфигурации (перебор размеров окна, наборы v0.3/8 групп, на экране и вне его, сборки
  0.3.1 и 0.3.2). В 0.3.3 превью сделано облегчённым (`RadialView.Lightweight`: без DropShadowEffect и BitmapCache
  внутри Viewbox) и фиксированного размера. Если повторится — смотреть в log.txt запись `UiWatchdog`
  («Интерфейс не отвечает … экран: настройки: phrases»); при необходимости снять дамп процесса из диспетчера задач.
- **Доверие к обновлениям = доверие к GitHub-аккаунту.** SHA256SUMS.txt лежит в том же релизе, что и exe: это защита
  целостности, а не подлинности. Следующий шаг — подпись exe (Authenticode) или подписанный манифест с открытым ключом,
  зашитым в программу (закрытый ключ — в секретах GitHub Actions).
- **Режим администратора** при exe в пользовательской папке: задача Планировщика с наивысшими правами указывает на файл,
  который может подменить любая программа пользователя. В настройках показывается совет перенести exe в Program Files.
- Отката, если новая версия не запускается, нет (`.old` удаляется при старте новой версии).
